# v0.49.0 Release Notes

Artifact v0.49.0 is the Application Shell And Loading Boundaries release.
Public pages now load only what they need: home, docs, and account recovery
download between a third and a half of the JavaScript and about a third of the
CSS they did in v0.48.1, the static public pages arrive prerendered, and the
node canvas, renderer, PixiJS, and Three.js load only when a surface activates
them.

This release changes how the web app is split, styled per route, prerendered,
and hosted, and adds an automated route-loading gate. It deliberately does not
change public URLs, editor workflows, or the visual design.

Document schema, graph traversal, renderer/export behavior, thumbnail
scheduling, AI scope, package export, and font policy remain unchanged.

## Highlights

- Home, `/docs`, `/docs/nodes`, `/docs/recipes`, and `/docs/reference` are
  prerendered with their own title, description, and Open Graph and Twitter
  metadata, so they show real content before JavaScript runs.
- Editor, Projects, account, and other dynamic paths load through the SPA
  fallback, which now shows an accessible Artifact loading shell instead of a
  blank page.
- Initial JavaScript before first render (gzip) drops from 423.6 KiB to
  131.1 KiB on home, 240.4 to 119.2 KiB on docs, 239.6 to 119.6 KiB on account
  recovery, 312.8 to 218.7 KiB on Projects, and 414.4 to 321.6 KiB on the blank
  editor.
- Route CSS is owned by the route or component that uses it; the root
  stylesheet drops from 35.5 KiB to 9.1 KiB gzip, and home CSS from 38.4 KiB to
  12.6 KiB.
- React Flow, the renderer, PixiJS, and Three.js no longer load on public pages;
  the home hero renderer loads after first render, and the account dialog loads
  when sign-in opens.
- Site navigation animations use CSS instead of Framer Motion and stay off
  under reduced motion.
- A direct visit to an unknown path shows the not-found recovery page without a
  hydration error.

## Scope Boundaries

- Included: a checked-in route-loading contract with JavaScript and CSS budgets,
  prohibited eager dependency families, and owned exceptions for every
  representative route and activation state.
- Included: a minimal root shell, route-owned CSS, the hydration fallback, and
  static public prerendering with matching Vercel and preview hosting rules.
- Included: vendor and renderer chunks that follow the real import graph, and a
  `loading:gate` check in pull request CI and the release workflow.
- Deferred: editor layout, inspector, Layers graph tree, and input latency work
  are planned for v0.50 Editor UX.
- Deferred: AI-assisted creation remains v0.51 scope.
- Deferred: no runtime SSR service; dynamic, authenticated, and editor paths
  are not prerendered.

## Validation

Local validation passed during release prep on 2026-09-30:

- `npm run release:verify -- --version 0.49.0`
- `npm run check`
- `npm run build`
- `npm run loading:gate`
- `npm run test:browser:release`
- `npm run perf:node-editor`

The `check` run included 20 UI Foundation tests, 721 Web tests, 261 passing API
tests with 5 skipped, 11 Backoffice tests, 27 deployment tests, 20
route-loading contract tests, and 3 legacy-registry contract tests, plus
formatting, lint, and all type checks.

The route-loading gate measured every representative state within its
JavaScript and CSS budget with no prohibited eager dependency: before-render
JavaScript is 131.1 KiB gzip on home, 119.2 KiB on docs, 119.6 KiB on account
recovery, 218.7 KiB on Projects, 321.6 KiB on the blank editor, and 362.4 KiB
on the style guide; Nodes activation adds 119.4 KiB and first 3D activation
adds 182.5 KiB.

The complete browser release gate scheduled 718 scenarios across Artifact
Chromium, Firefox, WebKit, mobile Chromium, mobile WebKit, the production
preview navigation, public shell, CSS ownership, and prerender segments, and
Backoffice desktop/mobile Chromium: 587 passed without retry, 1 passed on
retry, and 130 were intentional skips. The retried scenario was the WebKit
showcase-to-editor smoke, whose first attempt logged a WebGL `loseContext`
warning.

`npm audit` reports 0 vulnerabilities after a clean `npm ci`.

Performance notes:

- `npm run perf:node-editor` passed. Drag, effect-control, and graph-pan
  interactions produced no long tasks; their p95 frame times were 9.6-9.7 ms
  against the preferred 50 ms budget.

## Manual QA

- On a production preview of the release build, confirmed that home, `/docs`,
  and `/docs/nodes` return prerendered HTML with their own titles and
  headings, and that `/app`, `/projects`, and an unknown path return the
  loading shell before the route loads.
- Confirmed the home page hydrates and reports `v0.49.0`; a blank editor opens,
  Nodes loads the node canvas, and adding a 3D Primitive loads Three.js only at
  that point and renders the primitive preview.
- Confirmed a direct visit to `/projects` and to an unknown path renders
  Projects and the not-found recovery page without a hydration error.

## Accepted Risks

- Style guide (362.4 of 370 KiB) and Projects (218.7 of 230 KiB) are close to
  their JavaScript budgets; the next route-level addition there needs a
  reviewed contract update.
- Dynamic paths show the loading shell until their route chunk arrives; only
  the five static public paths are prerendered.
- The WebKit showcase-to-editor smoke needed one retry in the local release
  gate after a WebGL context-loss warning; it passed on Chromium and Firefox
  on the first attempt.
- React Router 7.18 prints v8 future-flag warnings during the build. They do
  not change runtime behavior; adopting the flags is deferred to a dedicated
  upgrade.
