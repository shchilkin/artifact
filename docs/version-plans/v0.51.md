# v0.51 Core Reset

Status: release-ready as `v0.51.0`. Phases 0-6 landed on 2026-10-23 (#471).
One acceptance criterion has a recorded exception (storage-failure fallback,
Phase 6). Planned as v0.53, it took the next version number because it ships
first (see [`../version-planning.md`](../version-planning.md)). v0.51.0 also
ships the Editor Polish Patch fixes (#442-#447) planned as v0.50.1 in
[`v0.50.md`](./v0.50.md), which never shipped on their own. Release notes are
in [`../releases/v0.51.0.md`](../releases/v0.51.0.md).

## Purpose

v0.40 through v0.50 were all UI, AI, account, or shell releases, and every
plan from v0.42 to v0.50 carried the non-goal "no renderer, graph, document, or
persistence change". The engine kept every feature working, but each new
feature now costs more than it should:

- A new node type touches about 25 non-test files. A new effect parameter
  touches 10 to 12.
- Topology has two sources: `doc.layers` order and an optional `doc.graph`.
  About 25 call sites build a graph on the fly when it is missing, and layer
  insertion has three code paths.
- `CanvasGraph` keeps a separate array for each of 10 node kinds, so every
  operation on nodes is copied once per kind.
- `EffectLayer` is one flat record with about 110 fields. Which backend runs
  an effect is set by hand-kept key lists.
- `normalizeDocument` runs legacy splitting and migration code on every load.
- Document updates mix `snapshot`, `debounce`, and `silent` writes. Some silent
  writes change user-visible state without an undo entry.

The release thesis is: **adding a node type or an effect parameter is a local
change, and the document has one topology source**. Rendered output stays the
same.

## Scope

Phases land in order. Each phase is a separate PR that keeps the render
fixtures green.

### Phase 0: Process reset and known bugs (done)

- One instruction file: `AGENTS.md`. `CLAUDE.md` and
  `.github/copilot-instructions.md` point to it; `COPILOT.md` is removed.
- Shipped version plans, finished inventories, Fallow baselines,
  `improvement-plan.md`, `ui-overhaul.md`, the old roadmap, and per-release
  evidence moved to `docs/archive/`.
- One release-gate definition (`docs/production-readiness.md`). The release
  verifier no longer requires manual roadmap or production-readiness edits.
- Fixed: splitting a legacy combined effect layer left `doc.graph` pointing at
  the removed layer id, so the split layers were disconnected.
- Fixed: `rgbSplit` ran in both the Canvas 2D worker and a GPU filter, so the
  split was applied twice.

### Phase 1: Safety net

- Done: golden render fixtures for every starter, curated example, and hero
  frame (33 documents), in stack and bootstrapped-graph mode, at preview and
  export size. See `docs/testing.md` ("Golden render fixtures").
  - Pixel hashes are exact, not tolerance-based, and run in the pinned CI
    Playwright container (`npm run test:golden`). Measured macOS vs Linux
    differences from system fonts and emoji reached 21% of pixels, so a
    cross-platform tolerance would hide real regressions.
  - Export at 2x and 3x is a nearest-neighbour upscale of the 1x canvas, so the
    meaningful sizes are preview (540px) and export base size.
  - GPU filter recipes (filter, shader hash, uniforms) are pinned on every
    `npm test`.
- Finding: 18 of 22 stack documents render differently after the editor
  bootstraps a graph for Nodes mode. Documents that rely on `global.bg` without
  a fill layer lose the background in graph mode (mean alpha 122 instead of 255
  on `hero-0`), and effects then run over transparent pixels. Recorded as
  `stackMatchesGraph: false`; Phase 3 must fix it. Not yet checked in the
  browser.
- Remaining: unit tests for `render/layers`, `render/graph` node renderers,
  `effectLayerMigration`, and `renderSignature`.

### Phase 2: Migrations as one-shot steps (done)

- `utils/migrations/` holds `v1ToV2`, `v2ToV3` (with the AI-shader GLSL code
  generation in `legacyAiShaderGlsl.ts`), and a new `v3ToV4` step, registered in
  `MIGRATIONS`. Each has a fixture test; the generated legacy GLSL is pinned
  byte for byte.
- `DOCUMENT_SCHEMA_VERSION` is 4. The 3 -> 4 step took over every legacy branch
  `normalizeDocument` used to run on each load: `kind: 'source'` aliases,
  0-100 material percentages, removed shader kinds (and `staticMeshGradient`
  distortion), and combined effect splitting with graph rewiring.
  `normalizeDocument` now only fills defaults and validates
  (`documentPersistence.ts` 1140 -> 710 lines).
- Golden fixtures also assert that `normalizeDocument` does not change the
  pixels or GPU recipe of any shipped document.
- Changed from the original plan: hero frames and effect thumbnails keep
  building layers from multi-effect patches. The field-ownership rules are not
  legacy; they moved to `utils/effectPresetPatch.ts` (authoring helper), which
  derives them from the effect parameter schema since Phase 5.
- Compatibility: builds before v0.51 reject schema 4 documents and share links
  ("Unsupported document schema version"). Release notes must say so.

### Phase 3: Graph is the only topology source (done)

- Background fix first: the export node painted `doc.global.bg` only for stack
  renders, so a document relying on its background lost it once Nodes
  bootstrapped a graph (18 of 22 golden stack documents). The background is now
  painted in every mode; `bg: 'transparent'` stays transparent. Only the
  graph-mode renders of those 18 documents changed, and every golden stack
  document now matches its graph pixel for pixel.
- Schema 5: `CanvasDocument.graph` is required. The 4 -> 5 migration gives a
  graphless document its linear graph; `makeDocument` does the same for
  documents built in code. `inferLinearGraph` and `EXPORT_NODE_ID` moved to the
  leaf module `types/linearGraph.ts`.
- Removed: `documentGraph()` and every `doc.graph ?? inferLinearGraph(...)`
  fallback, `bootstrapDocumentGraph` and the silent bootstrap on entering Nodes,
  the no-graph branches in layer insertion, update, delete, and duplicate
  commands, and the `graphMode` render option (nothing needed a stack render of
  a custom graph). `renderDocument` always renders `doc.graph`.
- Layer-list edits on a layer-stack graph keep the graph equal to the stack
  (`keepStackGraphInSync`). This also fixes remove and duplicate on documents
  that had visited Nodes: removing a middle layer used to break the chain, and
  a duplicate became an unconnected node.
- The layer preview's per-layer prefix cache is now chosen by graph shape
  (`isLayerStackGraph`) instead of by "has no graph", so documents that visited
  Nodes keep the cache too.
- Four graph recipes are layer stacks in practice and now also get `stack`
  golden renders; no existing baseline hash changed.
- `?doc=` links leave out a layer-stack graph that the layers fully determine
  (`utils/documentLink.ts`); the full graph pushed showcase links past the dev
  server's header limit (HTTP 431).
- Changed from the original plan: `graphMode` was removed instead of reduced to
  `stack | graph`.
- Finding for Phase 6: since Phase 0 no focused effect preset has both a
  Canvas 2D and a GPU part, so the v0.50 `mergeGpuPasses` path only runs for a
  hand-built multi-backend layer (as in `v050-gpu-readback-parity.spec.ts`).
  Removed in Phase 6.

### Phase 4: Node-kind registry (done)

- Schema 6: `CanvasGraph.nodes: Record<id, GraphNode>` with a `kind`
  discriminant replaces the ten per-kind arrays. The 5 -> 6 step moves them in
  the old classification order; on an id collision the first kind wins, as the
  old lookups did.
- A kind is defined in three modules, not one, because the loading contract
  keeps the renderer and the node canvas off routes that only need the model:
  - model, `utils/nodeKinds/<kind>.ts`: type, factory, normalizer, render
    inputs, render signature, insertion, `afterUpdate`, canvas look, Add
    Library data (`GRAPH_NODE_MODELS`);
  - renderer, `utils/render/nodeKinds/<kind>.ts` (`GRAPH_NODE_RENDERERS`);
  - editor UI, `components/node-canvas/nodeKinds/<kind>.tsx`: React Flow node
    (`GRAPH_NODE_UIS`), with its inspector wired in `GRAPH_NODE_INSPECTORS`.
    The inspector registry is separate so the Properties panel (and the style
    guide that shows it) does not load every React Flow node component.
- Generic code iterates the registries: normalization, insertion, deletion,
  render dispatch, render reach, render signatures and thumbnail caches, React
  Flow `nodeTypes`, edge colors, canvas symbols, Layers tree helpers, the
  Properties panel, target summaries, and Add Library entries, intents, and
  labels. `ADD_NODE_ITEMS` (unused) was deleted.
- `nodeKindLocality.test.ts` proves the criterion: grime shadow appears only in
  its model, renderer, UI, and inspector files, one line in each of the four
  registries, the frozen 5 -> 6 migration, and the public node reference copy.
- Changed from the original plan: four registry lines instead of one, as
  above. The home hero's after-render budget moved from +185 to +188 KiB: the
  renderer split cost +2.5 and the model's look and Add Library data +1.6
  (`docs/loading/route-loading-matrix.md`).
- Golden recipes, pixel hashes, and `stackMatchesGraph` are unchanged.
- Finding for Phase 6: inserting an environment node from the library feeds the
  Scene 3D `env` port through the generic `{ through: port }` insertion; kept
  as before.

### Phase 5: Effect parameter schema (done)

- `types/effectSchema.ts` (leaf module) declares the 110 effect parameters
  (`EFFECT_PARAMS`: owning effect, label, default, slider range or color,
  value format, help key) and the 61 render effects
  (`EFFECTS`: backend `canvas | worker | gpu`, the amounts that turn them on,
  activation rule, help family). `EFFECT_SECTIONS` places every parameter in
  one inspector section; `EFFECT_PRESET_VARIANTS` describes the five codec
  block presets that share the Bad Stream effect.
- Derived from it: the `EffectLayer` parameter fields,
  `DEFAULT_EFFECT_LAYER_PROPS` (same key order), `ZERO_EFFECT`, the Canvas 2D
  and GPU activation checks, inspector sections and controls, section preset
  groups, preset splitting for hero frames and effect thumbnails, docs
  parameter lists and ranges, help families, and preset randomizers (the
  randomizers were removed in Phase 6 as unused).
- Proof: the old tables were snapshotted before the change and compared after
  it. Defaults, key order, zero values, presets, menu order, controls,
  backends, and split rules are identical; all 66 preset randomizers give the
  same values for the same random draws. `effectSchema.test.ts` checks that
  every parameter has one control and every effect has one backend, and it
  renders every effect: GPU effects build filters only, worker effects send
  pixel-worker operations, and canvas effects change Canvas 2D pixels without
  either.
- Golden recipes, pixel hashes, and `stackMatchesGraph` are unchanged.
- User-visible changes, all corrections:
  - The RGB Split preset showed two sliders for the same field (Glitch
    "Chromatic" 0-15 and Color "RGB Split" 0-30). It now has one, "RGB Split"
    0-30 in Glitch.
  - Effect docs ranges now come from the controls. Nine stated a different
    range than the control (for example Glitch 0-100 where the slider is 0-24,
    Tint opacity 0-100 where it is 0-80), and others mixed up slider and typed
    limits.
  - Slider help shows a family for secondary sliders of a family's effect
    (for example hatch scale and angle).
- Changed from the original plan: there is no separate zero value or step.
  Every amount defaults to 0, so `ZERO_EFFECT` is the defaults; no effect
  slider uses a non-default step. The effect render signature was already
  generic (every effect field) and is unchanged. Preset metadata
  (`EFFECT_PRESETS`), slider help copy (`effectInfo.ts`), docs descriptions,
  and section summaries stay hand-written copy.
- The schema 3 -> 4 migration keeps its own frozen split rules
  (`migrations/legacyEffectSplit.ts`), so schema changes cannot change how old
  documents migrate.
- Removed test-only code: `randomLayerSection` and `zeroLayerSection` (classic
  section randomizers), and the per-section preset arrays in
  `node-canvas/constants.ts`.

### Phase 6: Commands, history, and cleanup (done)

- Dispatcher: every durable edit is a named command in
  `utils/documentDispatch.ts` that declares its history policy. Node canvas
  graph edits name what the user did (`GraphEditKind`), and
  `GRAPH_EDIT_HISTORY` maps each kind to a policy. Sidebar and node canvas no
  longer pass whole documents or choose modes.
- History: a pure reducer (`documentHistoryReducer`: commit, settle, undo,
  redo). `useEditorDocument` has no raw document setter; undo and redo are
  reducer events. Two bugs fixed with tests: a discrete action within 400 ms
  of a gesture dropped the gesture's undo step, and undo during a gesture went
  one step too far.
- Silent writes: entry placement and stored image sources amend every history
  entry the same way, so undo cannot bring back the unplaced layout or the
  embedded payload. Exception: when the browser cannot store a font, model,
  or environment payload, the payload is dropped from the current document
  (`stripPortableDocumentAssets`), which can change output. It is the
  existing storage-failure fallback; keeping it was chosen over a payload
  that no longer fits local storage.
- History behavior changes: visibility, area, rename, and image-replace
  actions in Layers, and connect, disconnect, move, organize, and area edits
  in Nodes, are one undo step each instead of being joined by the 400 ms
  debounce.
- Splits (no production file in `utils/`, `types/`, or `hooks/` over 800
  lines, enforced by `sourceFileSize.test.ts`): `types/config.ts` 1436 -> 609
  (`effectPresets.ts`, `materials.ts`, `layerIds.ts`),
  `render/layers/index.ts` 1353 -> 444 (`drawLayers.ts`, `canvasEffects.ts`,
  `badStream.ts`), `starterDocuments.ts` 1082 -> 45, the pixel worker
  939 -> 88, `useDocumentRenderer.ts` 987 -> 372. `render/graph.ts` and
  `documentPersistence.ts` were already under the limit after Phases 3-4.
- Cleanup after Fallow production traces (no production references):
  `resolveRenderOrder`, `resolveUpstreamRenderLayers`,
  `collectDownstreamNodeIds`, `appendNodeToExportPath` (superseded by graph
  reach), the localStorage pre-blank draft writers (drafts are in IndexedDB;
  the legacy reader stays), `getInitialDocumentFromSources`,
  `updateGlobalInDocument`, `InspectorLabel`, the old node canvas UI reducer
  (replaced by the XState machine), and two unused re-exports.
- Phase 3 finding resolved: the `mergeGpuPasses` preview path is removed. No
  document made of focused presets reached it.
- Phase 4 finding fixed: inserting an environment node on a connection fed
  the connection into `env`, which the node does not render, so the chain
  lost its image. It now goes through `in`.
- Removed on the owner's decision: the per-preset effect randomizers
  (`randomEffectLayer` and the schema's `random` ranges from Phase 5),
  `randomEmojiLayer`, `randomTextLayer`, `randomGlobal`,
  `randomDocumentFromSeed`, and `cancelAiGenerationJob`. None had a
  production caller after the classic section randomize buttons were removed.
  The editor's Randomize (`randomDocument` and its formulas) is unchanged. A
  future per-effect Randomize action brings its ranges back with it.
- Golden recipes, pixel hashes, and `stackMatchesGraph` are unchanged.

## Non-Goals

- No new node kinds, effects, AI features, or UI surfaces.
- No intentional change to rendered pixels. A fixture diff in Phases 1-6 is a
  bug unless the plan is amended first.
- No visual redesign of the editor. UI changes are limited to wiring inspectors
  and Add Library to the registries.
- No backend, account, or backoffice change.
- No GPU visual-regression suite (that needs its own tolerance plan).

## Acceptance Criteria

- [x] Phase 0: one agent instruction file, `docs/` holds only current docs plus
      `docs/archive/`, and the two known bugs have regression tests.
- [x] Golden fixtures cover all starter, hero, and example documents in stack and
      graph mode, and pass unchanged at the end of every phase (fixtures exist
      since Phase 1). The one engine-caused baseline change was the approved
      Phase 3 background fix. The first CI run of the pixel job (PR review)
      showed that text fell back to different system fonts in CI and in local
      Docker; golden runs now pin fonts (`pinGoldenFonts.ts`) and the text
      cases' hashes and thumbnails were regenerated for that, with GPU recipes
      unchanged.
- [x] `stackMatchesGraph` is `true` for every golden case.
- [x] `normalizeDocument` contains no legacy-format branches; each migration is
      a versioned step with a fixture test.
- [x] No code substitutes an inferred graph for `doc.graph`. `inferLinearGraph`
      runs only when a document is created (schema 5 migration,
      `makeDocument`) or when Layers edits rebuild a layer-stack graph.
- [x] Adding a node kind is its own modules (model, renderer, UI, inspector)
      plus one line per registry, proven by moving an existing kind (grime
      shadow) into the registry without touching generic files
      (`nodeKindLocality.test.ts`). Amended in Phase 4 from "one module plus
      one entry"; see the Phase 4 notes.
- [x] Adding an effect parameter is one schema entry plus its render code,
      proven by a test that every schema key has exactly one backend and a
      control (`effectSchema.test.ts`).
- [x] No production call to the raw document setter outside the dispatcher, and
      no silent write that changes visible state, except the storage-failure
      fallback recorded in Phase 6.
- [x] No production source file over 800 lines in `utils/`, `types/`, or
      `hooks/` (`sourceFileSize.test.ts`).

## Validation

- `npm run check`
- `npm run build`
- `npm run test:browser`
- `npm run perf:node-editor` for Phases 3, 4, and 6 (node editor paths)
- `npm run test:golden` on every phase PR (CI job `render-golden`)

## Rules During The Reset

- A phase PR may change engine internals freely. It may not change rendered
  output, the stored document format without a migration, or user-visible
  behavior.
- New feature work that needs a new node kind or effect parameter waits for
  Phase 4 or Phase 5, so it lands on the registry instead of adding another
  copy.
