# v0.48.1 Release Notes

Artifact v0.48.1 is the Custom Graph Preservation and Dependency Security
patch. Adding or reordering layers from Layers no longer rebuilds a custom node
graph into a linear chain, so merges, masks, 3D scene inputs, and node positions
survive Layers edits. The release also clears every known dependency advisory.

This release changes how Layers commands edit an existing custom graph, how the
Layers panel offers reorder for it, and which dependency versions ship. It
deliberately does not change graph traversal, rendering, or any stack-only
document.

Document schema, graph traversal, renderer/export behavior, thumbnail
scheduling, AI scope, package export, and font policy remain unchanged.

## Highlights

- Adding a layer from Layers to a custom graph inserts it just before Output
  and leaves every other connection and node position in place.
- Layer-stack reorder is disabled for custom graphs; the Layers panel explains
  that layer order follows the node graph and is edited in Nodes.
- Layers can still be dragged out of an area in a custom graph, because area
  membership is organization rather than composition order.
- A 3D scene added from Layers keeps its primitive, material, and environment
  inputs when more layers are added afterwards.
- Documents whose graph is a plain layer stack keep the previous add and
  reorder behavior.
- Updates React Router to 7.18.4, Vitest to 4.1.11, and patched transitive
  dependencies including Vite tooling, PostCSS, `ws`, `qs`, Express 4, and
  `body-parser`; removes the unused Puppeteer dependency. `npm audit` reports
  0 vulnerabilities, down from 27.

## Scope Boundaries

- Included: graph-preserving Layers add and reorder commands for custom graphs.
- Included: the Layers panel reorder state and explanatory note for custom
  graphs.
- Included: removal of an unused internal insert-above code path.
- Included: dependency updates within the current major versions and removal
  of unused Puppeteer.
- Deferred: showing custom graphs as a structured Layers tree and editing runs
  inside it are planned for v0.50 Editor UX.
- Deferred: no layout, inspector, performance, or visual changes to the editor.
- Deferred: React Router v8 future flags are not adopted.

Local validation passed during release prep on 2026-09-29:

- `npm run release:verify -- --version 0.48.1`

The `check` run included 20 UI Foundation tests, 719 Web tests, 261 passing API
tests with 5 skipped, 11 Backoffice tests, 26 deployment tests, and 3

The complete browser release gate scheduled 554 scenarios across Artifact

skips.

Pull request CI for the fix passed the quality, Fallow, and browser jobs for

Performance notes:

- `npm run perf:node-editor` was not required because this patch changes no
  graph traversal, renderer path, render signature, thumbnail queue, pointer
  geometry, or node-editor interaction hot path.

## Manual QA

- Opened a document with two fills merged into Output, added a text layer from
  Layers, and confirmed the merge connections and the positions of the existing
  nodes were unchanged, the text layer was connected between the merge and
  Output, and the title rendered over the merged result.
- Confirmed the same document shows the graph-order note in Layers with row
  dragging and drag handles disabled. Linear-document drag reorder is covered by
  the browser release gate.

## Accepted Risks

- Custom graphs cannot be reordered from Layers until the v0.50 Layers graph
  tree lands; users reorder those graphs in Nodes.
- A layer added from Layers to a custom graph without an Output connection
  becomes the only Output input.
- React Router 7.18 prints v8 future-flag warnings during the build. They do
  not change runtime behavior; adopting the flags is deferred to a dedicated
  upgrade.
