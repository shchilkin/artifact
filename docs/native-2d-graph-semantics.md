# Shared 2D graph semantics (P04)

Issue [#264](https://github.com/shchilkin/artifact/issues/264) is implemented on the coordinator-approved stacked P03 commit `1c20ec2186bbd0fe3b2e7aa8465dc09a28bcbf5e` (draft PR #282). The P03 parent and foundation are not claimed merged. This module is the shared graph command and dependency contract. P05 adopts it in the main Web editor; P09 consumes its dependency snapshot for native rendering; P10 supplies native node gestures. Those real-client milestones remain separate.

`DocumentSession` accepts `{"type":"graph","action":{...}}` inside the P03 version 1 `update_transaction_json` envelope. Actions cover six 2D utility collections, node patches, multi-delete/duplicate, positions, create/remove/reconnect/split edges and graph areas. Creation fills omitted known fields with the current Web factory defaults; typed patches validate Web inspector enums, ranges, booleans and integer counts. Unknown extension fields on a new node are retained. Graph operations use the existing transaction journal, one Undo/Redo timeline and atomic update rollback. Deleting a locked layer-backed node rejects the whole action. This is deliberately stricter than the current Web helper, which filters locked IDs and partially deletes the rest; P05 must reconcile the client with the atomic shared contract. Layer-backed duplication remains disconnected, matching Web's existing graph duplication flow. A missing graph field is stack mode; a graph action never materializes or linearizes it. Graph-only gesture ticks copy graph metadata and small layer descriptors, not asset payloads.

An edge has one `out` source and a target port appropriate to its 2D node. Creating or reconnecting to an occupied target port replaces that port's previous edge, like `addGraphEdge` in Web. Cycles reject atomically with `INVALID_VALUE`, including split/reconnect. Edge array order determines upstream DFS order. Existing unsupported graph node collections and unknown fields are preserved through unrelated 2D edits; attempts to directly edit unsupported nodes or their incident edges reject. Areas only group nodes and never change the dependency path. Moving a node into an area removes it from other areas as in Web.

An imported array-valued graph field ending in `Nodes` is treated as an opaque future node collection for topology bookkeeping. Its entries need unique valid IDs, including no collision with layers or known utility nodes. The shared commands preserve the collection without interpreting or editing it; a selected path through one of its nodes reports `renderable2d: false`. Other unknown fields, including non-array metadata, remain opaque data. Reconnecting an edge to its existing source, target and target port is a no-op: it retains edge order, document bytes, revision and Undo history.

The existing P03 layer commands also accept explicit supported 2D branches. Adding or duplicating a layer creates a disconnected node, removing one deletes its incident edges without bypassing the branch, and moving one changes layer-array order without rewriting graph edges. Affected unsupported layers or edges and locked deletion/reordering still reject atomically. The older linear-chain editor path retains its existing insertion/bypass behavior, and a document without `graph` remains stack mode. No structural operation silently converts a branch to a chain.

Both `WebSession` and `NativeSession` expose `graph_plan_json(target_id)`. It returns immutable JSON with explicit `mode`, target, upstream dependency nodes and port-bearing edges, render layer IDs, editor layer order (which appends disconnected layers), downstream IDs, disconnected node IDs, connected ports and deterministic layout order/depth inputs plus authored positions. `renderable2d` and `unsupportedNodeIds` report whether the selected path contains an unsupported node, including stack mode. Positions and areas do not enter render dependencies. Stack mode returns layer-array order without creating a graph. This plan describes semantics; it does not render pixels, choose node geometry or replace the main Web renderer.

Validation: `cargo test -p artifact-core --test graph` exercises independent expected paths and transactions. `npm run test:core-graph-web` compares WASM results to the existing pure Web helpers for edges, output path, layer order, connected ports and cycle behavior. It is included in `check:core-web`. `tests/core-commands/verify.mjs` is the cross Rust/WASM/Swift command and graph-plan fixture gate included in `check:core-native`. Run `npm run build:core-wasm-canonical` after the final Rust source change, then `npm run check:core-web`, `npm run check:core-native` and `npm run quality:native-2d-contract`. The source-linked capability matrix records this as command/model evidence, not native GUI, pixel or performance acceptance.
