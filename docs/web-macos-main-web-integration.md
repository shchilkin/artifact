# Main Web integration of the shared core

The Web pilot at port 4186 is a test harness, not a replacement editor. Product
work targets `apps/web` and the SwiftUI app. The main Web preview for this local
checkpoint is at `http://127.0.0.1:4187/app`.

## Implemented boundary

`useEditorDocument` warms the WASM module once when the real editor mounts.
`documentCommands.updateLayerInDocument` routes supported property patches to
`@artifact/core-web/commands`. That adapter calls Rust `patch_layer`, which uses
the same property command implementation as native `NativeSession.execute`.
This covers names, visibility/lock, opacity, text content/size/color/alignment,
image/text placement and supported fill/emoji/effect controls.

Only changed fields and minimal validation context cross WASM. Unchanged image
payloads, fonts, other layers and graph metadata are not serialized per slider
update. Unchanged document objects preserve their references. No Rust session or
second history stack is retained inside the Web editor: `useEditorDocument`,
`documentHistory`, localStorage and IndexedDB keep their existing ownership.

Before WASM is ready, on a load failure, or for fields/ranges outside the current
Rust contract, the original Web command runs. In particular existing asset
references, advanced effect/source fields, built-in font IDs and broader Web
coordinate ranges continue to work. This is incremental command integration,
not full engine parity. Native structural commands are not yet the main Web
graph implementation. The production Web renderer, graph helpers and GPU/3D
paths remain unchanged.

## Runtime distribution

Generated WASM/JS/type bindings are checked in under
`packages/artifact-core-web/generated`. This lets the existing Node-only Web
build and deployment environments build without a Rust toolchain. The main Web
build and typecheck verify `manifest.json` against the Rust sources, Cargo lock
and generated bytes, rejecting stale output. To update it:

```sh
npm run build:core-pilot -- wasm
```

Review and commit the generated runtime alongside source changes. The manifest
is a drift check, not a reproducible-build claim. The runtime is loaded lazily
from a same-origin Vite asset (currently about 395 kB, 140 kB gzip).

## Verification

- `sharedCoreCommands.test.ts` initializes the real WASM bytes and exercises
  production `documentCommands`, object preservation and Web-only fallbacks.
- Main Web: 98 test files / 724 tests, typecheck, lint, format and production build.
- Chrome main editor: add text, rename/content edits, undo/redo, Layers/Nodes,
  and PNG download. No console warnings/errors during this flow.
- The pilot remains useful for adapter conformance and private Viber fixtures;
  it is no longer the product acceptance surface for Web features.

This is local branch work. No production deployment or release has occurred.
