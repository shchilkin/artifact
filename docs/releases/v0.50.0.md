# v0.50.0 Release Notes

Artifact v0.50.0 is the Editor UX release. The editor keeps a stable layout,
responds to direct edits within measured budgets, shows what it is doing, and
presents custom node graphs truthfully in Layers: selecting a layer or switching
between Layers and Nodes no longer moves the canvas, slider edits reach the
preview within 50 ms, Layers and Nodes share one inspector layout, and custom
graphs appear in Layers as an editable tree.

This release changes editor workflow surfaces (Layers, Nodes, the inspector,
the command bar, and Add Library) and adds an automated editor UX gate. It
deliberately does not add node kinds, effects, or presets, and does not change
the visual system.

Document schema, graph traversal, renderer/export behavior, AI scope, package
export, and font policy remain unchanged. Thumbnail and interactive-preview
scheduling changed as described below; the full-quality preview, thumbnails,
and export produce the same output as v0.49.0.

## Highlights

- A stable editor frame: on desktop the inspector column is always reserved
  (with an empty state when nothing is selected) above one full-width command
  bar that Layers and Nodes share, so selecting a layer, switching modes, and
  opening Add Library move the canvas 0 px with 0 layout shift. The mobile
  command bar lays out in two rows without overlapping commands.
- Nodes fits the whole graph on first entry and restores the viewport you left
  on later visits.
- Faster direct edits: slider input is coalesced, preview renders run
  latest-wins with one render in flight, and the interactive preview frame
  renders smaller on slow GPUs. On the CI reference runner a slider keypress
  reaches the preview in 36.8-37.6 ms (62.4-121.8 ms in v0.49.0), and a 20-step
  drag spends 116.8-122.8 ms on the main thread. A drag is still one undo
  entry.
- Node thumbnails render near their on-screen size at the current zoom and
  queue visible and selected previews first; GPU readback no longer blocks the
  main thread.
- One inspector layout for Layers and Nodes: the same target shows the same
  sections in the same order, every slider row has a label, range, and numeric
  entry, and sliders and section toggles have accessible names.
- Explicit editor state: preview and render progress, an in-app confirmation
  dialog for New, Randomize over unsaved changes, opening a project over
  unsaved work, exporting a package with font files, and deleting a shared
  node from the Layers tree (no browser `confirm` prompts), a "not in output"
  status on Layers rows that the renderer does not reach, and an opaque Add
  Library surface with one filter axis.
- Custom node graphs appear in Layers as a graph-derived tree: merges as
  folders, mask, repeat, and Scene 3D inputs nested under their consumer,
  shared nodes listed once with reference rows elsewhere, a "Not in output"
  section, and a Structure/Areas switch.
- The Layers tree can reorder rows within a run, move rows between runs, add
  above the selected row, and delete with reconnection; each edit is one undo
  step and leaves every edge outside the edited run in place.

## Scope Boundaries

- Included: a checked-in editor UX contract with layout-shift, frame-movement,
  command-bar, inspector, input-latency, and preview-settle budgets, measured on
  the production build by `npm run ux:gate` in pull request CI and the release
  workflow. No budget exceptions remain.
- Included: the stable editor frame, input and preview latency work, the
  unified inspector, explicit editor states, and the read-only and editable
  Layers graph tree.
- Deferred: grouping rows into a new merge, wiring side inputs, and creating
  fan-out from Layers stay in Nodes.
- Deferred: AI-assisted creation remains v0.51 scope.
- Deferred: no token or visual-system redesign, and no native client work.

## Accepted Risks

- Latency budgets are measured on the CI reference runner with software
  WebGL. There the interactive preview frame renders at 270 px instead of
  540 px to meet the keypress budget, and the full-quality frame replaces it
  after the deferred-render delay. During an edit the interactive frame can
  look softer than the final preview; the final preview, thumbnails, and
  export are unchanged.
- Latency is scaled to a reference machine, so local numbers on other
  hardware are not comparable with the budgets; the CI gate decides.
- The style guide (367.2 of 370 KiB), Projects (220.9 of 230 KiB), and the
  blank editor (337.7 of 370 KiB, up from 321.6 KiB in v0.49.0) are close to
  their JavaScript budgets; the next route-level addition there needs a
  reviewed contract update.
- Grouping rows into a new merge, wiring side inputs, and creating fan-out are
  available only in Nodes. The Layers tree blocks moves of shared nodes,
  side-input tops, and locked layers.

## Technical Debt

- The Layers tree's per-kind input tables describe the renderer's graph inputs
  a second time instead of sharing the renderer's dispatch code. The shared
  renderer-backed reach fixtures keep the two in agreement.
- The interactive preview still paints a superseded pass during continuous
  input, one input behind, because dropping it left drags with no visible
  preview frames.
- `slider-drag/durationMs` is reported but not budgeted, because the CI drag
  loop cannot run faster than two frames per step; main-thread time is the
  budgeted drag metric.
