# v0.48 UI Conformance And Legacy Removal

Status: released as [`v0.48.0`](https://github.com/shchilkin/artifact/releases/tag/v0.48.0)
on 2026-07-27. Q1 through Q6 are complete: the finite legacy registry has zero
unresolved entries, both products share one executable Foundation conformance
contract, and the registered compatibility surface is removed behind a
no-reintroduction guard. Tag `v0.48.0` resolves to production commit
`bffb2630412d22daccf6501264d15fe419ed31ff`; exact-SHA staging, production API
contract, production web verification, and publication passed. Delivery was
tracked in GitHub milestone [`v0.48 UI Conformance And Legacy Removal`](https://github.com/shchilkin/artifact/milestone/5).

## Purpose

v0.48 closes the full UI rewrite by enforcing conformance across both products
and removing only legacy contracts with proven replacements and zero callers.

The release thesis is: Artifact and Backoffice have complete, enforceable
UI-system coverage with no unapproved legacy bucket.

## Scope

- Expand the migration inventory into an enforceable legacy registry.
- Migrate residual Artifact and Backoffice callers.
- Establish two-product visual and accessibility conformance.
- Contract deprecated primitives, aliases, exports, selectors, and CSS.
- Keep AI-Assisted Creation paused for v0.50; this release only unblocks the
  v0.49 application-shell gate.

The Q1 expand-phase contract is the machine-readable
[`UI legacy registry`](../ui-legacy-registry.json), with ownership and usage
guidance in [`ui-legacy-registry.md`](../ui-legacy-registry.md). Its automated
guard permits the allowlists to shrink but rejects new files, new occurrences,
unassigned routes, or Foundation Matrix identifier drift. Q1 performs no
deletion.

Q2 contracts every Artifact allowlist to zero by importing Foundation commands
and fields directly, using feature-folder entrypoints, adopting the
`artifact-inspector-*` anatomy, and replacing registered short token references
with semantic token families. The compatibility files remain registered until
Q5 proves they can be deleted without reintroducing callers.

Q4 uses the shared `tests/browser/uiFoundationTestHelpers.ts` assertions from
both Product Theme suites. Every registered Foundation specimen is checked for
readable geometry, while representative command, field, feedback, and overlay
states resolve their computed color, spacing, typography, focus, disabled,
error, loading, and reduced-motion behavior from the active Theme Contract.
Failure steps name the Product Theme, specimen identifier, CSS property, and
semantic token. Artifact runs across Chromium, Firefox, and WebKit; Backoffice
runs desktop and mobile Chromium in the required `browser (backoffice)` CI job.
Existing Artifact editor specimens and Backoffice operational specimens remain
the representative composed-surface proof.

Q5 closes the final relative-import gap in `SearchField`, removes the seven
registered compatibility files and only their bounded selectors, and switches
the registry to contract mode. The guard retains every removed import, selector,
token alias, and file path as a forbidden contract while preserving active
product-pattern stylesheets.

## Non-Goals

- No new product feature, design direction, or component-catalog expansion.
- No deletion without a proven replacement and zero registered callers.
- No renderer, graph, document, persistence, API, auth, or AI behavior change.

## Acceptance Criteria

- The inventory and legacy registry contain no unresolved, unapproved entry.
- Both Foundation Matrix routes expose the same v1 primitive/state identifiers
  under their respective themes.
- Representative product flows pass visual, responsive, keyboard, focus,
  reduced-motion, and accessibility conformance.
- Removed contracts cannot be reintroduced without failing an automated guard.
- Closing Q6 unblocks v0.49 Application Shell And Loading Boundaries. v0.50
  AI-Assisted Creation remains blocked until the v0.49 gate closes.
