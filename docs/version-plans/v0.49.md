# v0.49 Application Shell And Loading Boundaries

Status: planned. Blocked by the v0.48 release gate. Delivery is tracked in
GitHub milestone
[`v0.49 Application Shell And Loading Boundaries`](https://github.com/shchilkin/artifact/milestone/11).

## Purpose

v0.49 makes Artifact's production loading behavior intentional and measurable
before AI-Assisted Creation adds another large product surface.

The release thesis is: Artifact loads every representative route and state
through an owning application shell with explicit JavaScript, CSS, hydration,
and on-demand dependency boundaries.

## Scope

- Establish a checked-in route ownership, loading, and budget matrix from
  production build and browser-network evidence.
- Reduce the React Router root to genuinely cross-route document, recovery,
  token, theme, and outlet responsibilities.
- Give public, account, docs, Projects, editor, inspector, node-canvas, and 3D
  styles explicit route or component ownership.
- Add a product-appropriate hydration fallback and prerender only the static
  public paths approved by the loading matrix.
- Keep dynamic, authenticated, and editor routes on the deployable SPA
  fallback without adding a runtime SSR service.
- Make vendor, renderer, React Flow, PixiJS, and Three.js loading boundaries
  reflect actual dependency ownership and activation.
- Enforce route budgets and prohibited eager dependencies with deterministic
  automated checks.

## Non-Goals

- No AI-Assisted Creation implementation; it remains v0.50 scope.
- No public URL changes, broad visual redesign, or product-navigation rewrite.
- No renderer, graph, document, persistence, auth, account, or export semantic
  changes.
- No requirement for one standalone chunk-size warning to disappear without
  route-level user-impact evidence.
- No runtime SSR service or attempt to prerender dynamic, authenticated, or
  editor state.
- No manually named vendor chunk treated as proof of correct loading.

## Loading Contract

The first delivery issue owns the normative matrix. For each representative
route or activation state it must record:

- the owning root, route-family, route, or component shell;
- allowed initial chunks and prohibited eager dependency families;
- JavaScript and CSS budgets with explicit, reviewable exceptions;
- dependencies allowed only after graph, renderer, PixiJS, or 3D activation;
- whether the path is statically prerendered or served by the SPA fallback;
- the production manifest and browser-network evidence used to verify it.

The matrix must cover home, public docs, account recovery, Projects, blank
editor Layers, editor Nodes, style guide, and first 3D activation. It must not
depend on content-hashed filenames.

## Acceptance Criteria

- The loading matrix contains no unresolved or unowned representative route,
  budget, eager dependency, or exception.
- Root owns only cross-route document, recovery, token, theme, outlet, and
  proven shared behavior.
- Public routes do not receive editor-, inspector-, node-canvas-, React Flow-,
  PixiJS-, or Three.js-owned code or CSS before a matching surface needs it.
- Blank editor startup and first graph, PixiJS, and 3D activation respect their
  separate dependency contracts.
- Static public paths approved by the matrix are prerendered with correct
  content and metadata; dynamic, authenticated, and editor paths retain the SPA
  fallback.
- Direct and client navigation, auth/account actions, recovery, responsive
  navigation, focus, reduced motion, hydration, and production CSS ordering
  remain conformant.
- Preview, thumbnails, graph targets, 3D controls, and export retain canonical
  renderer behavior where loading boundaries change.
- Intentional budget or boundary changes require one reviewable contract update
  rather than a broad warning suppression.
- Closing L7 unblocks v0.50 AI-Assisted Creation but implements no AI scope.

## Validation

Focused implementation coverage must include production manifest assertions,
browser network evidence, direct and client navigation, hydration and
prerendering, responsive/account flows, editor activation boundaries, and
renderer regressions.

Required release gate:

```bash
npm run check
npm run build
npm run test:browser:release
npm run perf:node-editor
```

## Delivery Sequence

1. Record production build and browser-network evidence and approve the loading
   matrix.
2. Narrow root and route-family ownership without changing URLs or behavior.
3. Split CSS ownership and add the hydration/prerender boundary in parallel
   where the dependency frontier permits.
4. Make emitted dependency boundaries truthful and preserve on-demand
   activation.
5. Turn the matrix into the automated route-budget gate.
6. Run the complete release gate against the exact revision prepared for
   `v0.49.0`.

Each issue should fit one fresh implementation context and remain independently
verifiable. v0.49 is complete only when #244 closes.
