## Purpose

v0.50 makes the editor feel stable and trustworthy before AI-Assisted Creation
adds another large surface.

The release thesis is: the Artifact editor keeps a stable layout, responds to
direct edits within measured budgets, shows what it is doing, and presents custom
node graphs truthfully in Layers.

Primary blast radius: editor workflow (Layers, Nodes, inspector, command bar,
Add Library). Render, persistence, and export semantics are protected surfaces.

## Baseline Evidence

Measured on 2026-09-29 with Playwright against the dev server at 1440x900 on the
default document. Dev-mode timings are inflated; layout-shift values are not.
U1 re-measured on a production preview build; the normative numbers and
budgets are in
[`../editor-ux/editor-ux-baseline.md`](../editor-ux/editor-ux-baseline.md) and
[`../editor-ux/editor-ux-contract.json`](../editor-ux/editor-ux-contract.json).
The table below is the original planning evidence.

| Interaction | Observed |
| --- | --- |
| Select a layer | Inspector appears and the canvas moves 170 px left |
| Switch to Nodes | Layout shift 0.17 (bottom bar moves); 5 of 7 nodes outside the viewport |
| Switch back to Layers | Layout shift 0.53 |
| Inspector after visiting Nodes | Same slider renders 169 px, then 129 px; row layout changes |
| 20-step slider drag | 890 ms against an ideal of about 340 ms |
| Slider keypress to preview repaint | 102 ms |
| Mobile command bar (375 px) | Random is clipped under More; commands overlap |

Other observed issues: `window.confirm` for New, sliders announced only by value,
unnamed section toggles, the same layer row button named three different ways,
a translucent Add Library surface over the canvas, and Layers that cannot see or
edit most graph utility nodes.

## Scope

- A checked-in editor UX baseline with layout-shift, input-latency, and preview
  budgets that run in CI.
- A stable editor frame: the inspector column is reserved, the command bar has
  fixed zones, mode switches do not move the canvas, Nodes fits the graph on
  entry, and the mobile command bar does not overlap.
- Responsive direct edits: coalesced slider input, latest-wins preview
  scheduling, and a prioritized node-preview queue, all through the canonical
  renderer.
- One inspector layout for Layers and Nodes: label, control, and numeric entry
  on one row; primary controls first; accessible names for every control.
- Explicit states: preview and render progress, an in-app confirmation dialog
  for replacing or destructive actions, output-path status in Layers rows, and
  a legible Add Library surface.
- A graph-derived Layers tree for custom graphs, defined in
  [`../layers-graph-tree.md`](../layers-graph-tree.md), first read-only and then
  with safe run edits.

## Non-Goals

- No renderer, graph traversal, document schema, persistence, package, or export
  semantic changes. Preview and export parity rules in
  [`../rendering.md`](../rendering.md) stay unchanged.
- No new node kinds, effects, or presets.
- No token or visual-system redesign; v0.42-v0.48 Foundation contracts remain.
- No group-into-merge command, side-input wiring, or fan-out creation from
  Layers; those stay in Nodes.
- No AI-Assisted Creation scope; it moves to v0.51.
- No native client work (see ADR 0015).

## Acceptance Criteria

- Selecting a layer, switching Layers/Nodes in either direction, and opening Add
  Library each stay within the U1 layout-shift budget (target: 0.05 or less).
- Continuous slider edits meet the U1 input-to-preview budget on the reference
  documents in a production preview build.
- The inspector renders the same control layout for the same target in Layers
  and Nodes; every slider has an accessible name and numeric entry.
- No editor flow uses `window.confirm`; replacing work is confirmed in-app.
- Layers rows show whether a layer reaches Output.
- For every custom-graph fixture, the Layers tree contains exactly the nodes the
  renderer reaches plus a "Not in output" section, and shared nodes appear once
  with reference rows elsewhere.
- Every Layers tree edit is one undo step and preserves all edges outside the
  edited run.
- Preview, thumbnails, and export output are unchanged for existing documents.

## Validation

Focused coverage must include the U1 harness in CI, browser checks for layout
stability on desktop and mobile, tree-builder fixtures (linear, merge, mask,
repeat, Scene 3D inputs, fan-out, unreachable nodes, missing export edge),
graph-edit command tests, accessibility name checks, and renderer regressions.

Required release gate:

```bash
npm run check
npm run build
npm run ux:gate
npm run test:browser:release
npm run perf:node-editor
```
