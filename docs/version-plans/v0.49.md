# v0.49 Application Shell And Loading Boundaries

Status: planned. The release boundary and delivery issue granularity are
accepted. Delivery is tracked in GitHub milestone
[`v0.49 Application Shell And Loading Boundaries`](https://github.com/shchilkin/artifact/milestone/11).

## Purpose

v0.49 completes Artifact's move from a Vite-style single-page shell to explicit
React Router Framework Mode loading boundaries. Public pages provide useful
initial HTML or loading UI, route families load only the shell, styles, and
dependencies they own, and editor-only rendering libraries remain deferred
until the relevant surface needs them.

The release thesis is: Artifact loads each route through an intentional,
measured application-shell boundary before AI-Assisted Creation adds another
large product surface.

The release follows v0.48 UI Conformance And Legacy Removal and blocks v0.50
AI-Assisted Creation.

## Current Evidence

- React Router 7.14 Framework Mode already gives every registered route module
  an automatic code-splitting boundary.
- The Web application uses `ssr: false` without route prerendering or a root
  `HydrateFallback`, so the generated SPA document renders only the root shell
  before the matched route loads in the browser.
- The production root boundary currently transfers roughly 745 KiB of
  JavaScript uncompressed / 238 KiB gzip and 267 KiB of CSS uncompressed /
  40 KiB gzip before route-specific work.
- The global root stylesheet contains public-shell, editor, inspector, node,
  and responsive rules, so non-editor routes receive editor-owned CSS.
- Manual vendor groups no longer describe clean ownership: the client entry
  imports the emitted `flow-vendor` chunk while no separate `react-vendor`
  chunk is emitted.
- `three-vendor` and `pixi-vendor` remain absent from ordinary initial route
  imports. Their size warning is not evidence that they leak into non-3D or
  non-Pixi startup.

These values are a planning baseline, not permanent budgets. The first delivery
issue must produce a checked-in route matrix and explicit budgets before
optimization claims are accepted.

## Scope

- Define route-family ownership and production loading budgets from build
  manifests and deterministic browser network traces.
- Keep the root route limited to document shell, global tokens, recovery, and
  genuinely cross-route behavior.
- Move public, account, docs, editor, and style-guide composition behind the
  narrowest useful route or layout boundary.
- Split global CSS so public routes do not receive editor-, inspector-, node-,
  or 3D-specific selectors.
- Add a useful `HydrateFallback` and prerender the approved static public
  routes while retaining a SPA fallback for dynamic and editor routes.
- Replace misleading manual vendor grouping with boundaries that can be proven
  from the emitted build graph.
- Enforce the approved route budgets and prohibited eager dependencies in CI.

## Non-Goals

- No runtime SSR server or Node deployment requirement.
- No route URL, navigation label, authentication policy, or account behavior
  change.
- No renderer, graph, `CanvasDocument`, persistence, export, or provider
  behavior change.
- No rewrite of Three.js, PixiJS, React Flow, or the canonical renderer merely
  to reduce a vendor file's standalone size.
- No visual redesign of public pages, editor workflows, inspectors, or canvas
  chrome.
- No AI-Assisted Creation implementation.

## Acceptance Criteria

- A checked-in loading matrix names every representative route/state, its
  owning shell, allowed initial dependencies, prohibited eager dependencies,
  and approved JavaScript/CSS budgets.
- The root module contains no product-surface composition that can be owned by
  a narrower route family.
- Public routes do not receive editor-, inspector-, node-canvas-, or 3D-owned
  CSS.
- The generated static document presents a useful deterministic
  `HydrateFallback` instead of React Router's development warning shell.
- Approved static public paths are prerendered without introducing a runtime
  SSR service; dynamic/editor paths continue to work through the SPA fallback.
- Ordinary public and blank non-3D editor states do not request Three.js or
  PixiJS chunks before a matching surface needs them.
- Routes that do not render graph UI do not request React Flow after the vendor
  boundary is made truthful.
- Route-level JavaScript and CSS budgets are enforced automatically and pass on
  the exact release candidate.
- Existing URLs, auth behavior, editor behavior, preview/export parity, and the
  v0.48 visual/accessibility conformance contract remain intact.

## Validation

Focused implementation coverage must include:

- production manifest assertions for route ownership, initial imports, CSS,
  and prohibited eager dependencies;
- deterministic browser network traces for public, docs, account, blank editor,
  Nodes, style-guide, and first 3D activation states;
- browser coverage for direct navigation, client navigation, hydration
  fallback, prerendered paths, SPA fallback paths, auth/account actions, and
  recovery;
- responsive, keyboard, focus, reduced-motion, and production CSS-order checks
  for every shell moved behind a new boundary;
- preview/export and node-editor performance regression checks where loading
  boundaries touch editor entry points.

Required release gate:

```bash
npm run check
npm run build
npm run test:browser:release
npm run perf:node-editor
```

The exact verified revision must be promoted and tagged `v0.49.0` only after
the loading matrix and automated budgets pass in production-shaped output.

## Delivery Sequence

1. Lock the route/loading contract and budgets before moving imports or CSS.
2. Narrow the root and route-family shells.
3. Split CSS along the accepted ownership map.
4. Add hydration fallback and static public prerendering.
5. Correct vendor and renderer loading boundaries against the production graph.
6. Enforce the contract and close the full release gate.

Each issue must fit one fresh implementation context and preserve a useful
intermediate build. v0.49 is complete only when the release-gate issue closes;
individual chunk reductions are not release-complete by themselves.
